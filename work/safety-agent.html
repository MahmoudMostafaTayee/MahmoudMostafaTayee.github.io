Industrial safety Use case · VLM agent · bilingual · routed modes

Ask the camera what just happened. Get an answer a supervisor can act on.

Unsafe behaviour usually gets written up only after someone is hurt. The safety agent watches the last few seconds of a clip on request and answers in two modes: a structured hazard scan — severity-ranked, with certainty and evidence per hazard — or spoken-style chat for follow-up questions. Answerable in English and Arabic, because the people asking questions don't all share a language.

01The problem

An inspection is a report; a question is a conversation. The agent had to know the difference.

Merging the two modes conflates them: a hazard scan pasted into a chat feels robotic — and a chat answer to a safety-structured question buries severity and evidence. Both need the same context window (a few seconds of video as timestamped frames), different contracts, and different languages.

Design target: the hazard report never under-reports — uncertain hazards surface marked as possible, not hidden — and the chat stays short, spoken, and voluntary about anything serious it glimpses.

02Two modes, one router

A real routing per question type, in both languages:

  • Structured hazard scan. A safety-monitor persona biases toward reporting uncertain hazards as "possible" rather than missing them, then walks an on-camera checklist, returning JSON: answer, hazards ranked by severity (high / medium / low), each with certainty and evidence fields. The intent explicitly supports "possible" states — a hedge with structure beats silence.
  • Plain visual chat. Short spoken-style answers (a sentence or two, no markdown, no emoji), each carrying conversation history. If the frames contain a serious hazard the user didn't ask about, the agent mentions it briefly — safety conversations don't need permission slips.

The two modes share the context packaging: the last ~4 seconds become three timestamped frames, oldest to newest, with the newest labelled "current view" — enough motion context for a question like "was that runner too close to the forklift?".

03The hazard checklist

The scan's power comes from enumerating what a trained eye looks for, so it is only ever missing by being wrong, never by not being asked: PPE state; vehicles vs pedestrians (proximity rules expressed in scene units — a couple of forklift-lengths); suspended loads; edges and heights; machinery guards; housekeeping; fire/electrical/chemical; lone-worker and unsafe-behavior patterns. Output is sorted by severity; the evidence frame for each hazard arrives with the verdict for quick verification.

Product demos for the agent were built honestly and deterministically: the demo tooling recreates the real production request shape (prompts dumped from the actual agent source, not rewritten), captures real model answers per scenario timestamp, then renders the UI as a pure function of time — every typed character, streaming token, and hazard reveal keyed to a single time variable — screenshot per frame and encoded to video. Full RTL support via translated layout strings. Nothing is fabricated beyond timing: the words are the model's, replayed in motion instead of on screenshots.

05Reflection

Certainty and evidence as first-class fields: that's the difference between a demo and a tool.

The agent is judged by whether its uncertain answers are legible — a "possible hazard, evidence: frame at t-2" is actionable the same way a confirmed one is, because the supervisor sees the frame too. The moment certainty became a field with a default bias toward surfacing risk, the system stopped being a chat toy and started being an inspection instrument.
