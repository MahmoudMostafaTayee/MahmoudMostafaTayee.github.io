Cognitive video intelligence platform Use case · temporal language events from live streams

Operators ask what happened over time. Detectors answer what is in this frame.

The bridge between those two questions is batching, prompting, and state. Frames from live streams are sampled into overlapping batches with YOLO pre-annotation, a vision-language model writes temporal observations and events, and three deduplication layers keep the event stream calm while the UI reads it live over WebSocket.

01The problem

A VLM fed random frames produces narration, not monitoring.

Vision-language models understand human scenes but not streams. Frame-by-frame inference is too slow and too expensive; single-frame prompts produce misdated events and chatty repetition; a model without memory re-reports the same standing condition every cycle, drowning anything real. And under load, the system must shed history gracefully instead of queuing unbounded work while the "live" feed goes stale.

Design target: every cycle analyses recent footage on time; events are deduplicated, severity-anchored, and explainable; the model remembers changes, not snapshots.

02Batching the stream

  • Sample, don't interpret. A capture thread grabs and JPEG-encodes continuously; sampled frames accumulate in a small buffer so a batch of N frames always spans exactly the configured interval — the prompt states clip duration, frame count and effective fps (e.g. 10 frames ≈ 2.5 fps).
  • Overlap. Batches share a tail of frames, so an event crossing a cycle boundary appears in two consecutive calls and can be linked by context instead of being missed by a cut.
  • Drop-oldest backpressure. Completed batches queue in a bounded deque; if analysis is slower than the stream, the oldest batch is dropped and the loss counted. Freshness is the whole point of live monitoring — no analysis queue ever grows unbounded.
  • Fairness. With multiple cameras sharing one VLM worker, the camera analysed longest ago is served first, so no starved feed goes silent.

03Anatomy of a prompt

  • Persona + rubric. The system prompt encodes the monitoring role and an anchored severity rubric — moving vehicles near people are at least a warning, and the model may never report above its own stated level.
  • Pre-annotation. Tracks and per-timestamp class counts from YOLO ride along with the images, as guidance the VLM can lean on — geometry from a cheap model, meaning from the VLM.
  • History. Recent events grouped and capped per severity tier, with an explicit history-check instruction: don't re-report a standing condition unless it visibly worsened.
  • Schema. Output is structured — severity, category, one-sentence message, tags, optional location and recommended action — parsed defensively with severity clamping and garbage rejection.

04Three layers of dedup

  • Model-side history check against the recent events injected into each prompt.
  • Cooldown gates per event type per camera — comments and alerts get their own cadences.
  • Embedding dedup: message similarity against the last N recent messages of the same type; a suppressed message does not update the anchor, so a genuinely distinct new event can never be masked by a suppressed twin.

An optional scene-memory delta merges entity state, zone conditions and ongoing situations across cycles — the model reports the change, the platform accumulates the duration — and memory failure costs one stale cycle, never an event.

The browser sees two things: an MJPEG live view per stream, and a WebSocket that carries the last N saved events as history, then every new event live. A snapshot JPEG endpoint exists for one specific production reason — browsers cap concurrent connections per origin, and a mosaic of many live tiles exhausts them; snapshots multiplex over the normal pool instead. Events persist with severity, description, and clip references.

06Reflection

Treating the VLM as an engineering component, not a magic lens.

Everything that made this production-shaped lives outside the model: buffering policy, batch overlap, latency accounting, dedup layering, schema enforcement, connection management. The prompting was maybe a fifth of the work — the system around it determined whether the result was narration or monitoring.
