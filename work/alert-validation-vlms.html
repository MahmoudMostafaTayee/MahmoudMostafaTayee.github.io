Surveillance platform Use case · verdict + evidence, before the operator is disturbed

Every alarm deserves a second reader. Not every alarm deserves an operator.

Noisy classical analytics bury teams until they stop reading alerts. A validation stage re-reads each alarm with a vision-language model before it is surfaced — plain verdict, grounded evidence — and its own accuracy is measured with a logit-level benchmark and an offline record/replay harness that separates model quality from GPU contention.

01The problem

Precision is a trust budget. False positives spend it.

Classical analytics — motion triggers, line crossings, thermal fire heuristics — are cheap, constant, and confidently wrong: steam reads as smoke, headlights read as movement, shadows read as intrusion. The social failure is worse than the technical one: each false alarm is small, but a cadence of them teaches operators that the system speaks before thinking — and the real alerts get lost in the same channel.

Design target: nothing reaches an operator without a machine-readable verdict and the frames that justify it — and the validator itself is benchmarked, with uncertainty handled explicitly rather than hidden.

02The second pass

  • Interrogate, don't embellish. The validation prompt lists a taxonomy of classic false-positive causes for the phenomenon and asks the model to state plainly what is visible — a confident, well-grounded negative is explicitly framed as more useful than a hedge.
  • Grounded evidence. Frames are selected around the event timestamp, with the triggering zone's polygon drawn onto them, so the verdict is anchored to what a human would see in the same crop. No frames, no call — a fallback resolves the event with text instead of hallucinating evidence.
  • Confidence gating. On the search path a self-reported FOUND confidence below a threshold rejects the match: "when in doubt, not found" is encoded in the prompt, because a missed match is recoverable and a fabricated one is not.
  • Delivery. The verdict sentence attaches to the stored event and reaches the UI as an event-update over WebSocket — the operator reads the confirmation sentence and the evidence together.

03The validator

The standalone validator reviews alarms from motion/line-crossing analytics before an operator is disturbed, and is built as a benchmarked component rather than a prompt:

  • Input. Exactly what the validator would see at alarm time: the last 4 seconds as 3 timestamped frames — either as an ordered image sequence or a tiled "strip" image (a few hundred visual tokens). Prompt and input format were treated as first-class benchmark variables.
  • Forced-choice logits. Instead of generating text, a single forward pass reads the logits of the first answer token (ALERT vs FALSE). Cheapest possible verdict, yields a calibrated score for AUC-style analysis, and cannot produce an unparsable answer.
  • Live shape. Feeds are sampled at 1 fps; each new sample triggers one verdict over the trailing window. One shared worker serves all feeds oldest-first; stale samples are dropped and counted (never queued forever). A small per-feed debounce requires consecutive above-threshold verdicts to flip to alert — and to clear again.

04Record / replay evaluation

On live runs, the same model call sometimes answered in seconds and sometimes hung for minutes under shared-GPU contention — which conflates "the model's judgment is not good enough" with "the model never got GPU time". The harness separates them:

Goldhuman-verified identity labels
Recordevery eligible pair · JSONL + crops
Replaypluggable verdicts · no deadlines
Policytopology/Re-ID/VLM swaps
ReportP/R/F1 · false-merge count

Phase 1 records every candidate pair the decision point would ever face — including pairs today's gates silently decline — with crops, at full pipeline speed. Phase 3 replays verdicts through a pluggable provider interface (the deployed model with no deadline; a Re-ID-only threshold baseline; a paid-API stub) at temperature 0 to also measure verdict stability. Phase 4 re-clusters under policy swaps and scores against gold with pairwise precision/recall/F1, per-chain completion, and a false-merge count — the stakeholder-critical number. If the shipped policy matches gold once contention is removed, the fix is latency engineering, not a model upgrade.

Honest caveats are part of the design: the accuracy test set is small and deliberately scoped — it demonstrates feasibility, not generalization, and the written-report mode is a different regime (near 10× the cost, and only one model build produced correct reports). The soak numbers include the headroom verdict: ~13% headroom is not a capacity claim, and cost depends on input shape.

06Reflection

A validator that hasn't been benchmarked is a prompt, not a component.

The three things that made alert validation real were: making the verdict cheap and parsable (logit choice instead of generation), making evidence mandatory (frames drawn with the zone before any judgment), and making evaluation replayable (record everything, judge offline, swap policies). Recording every eligible pair — not just the greedy pick — turned out to be the discipline that made model upgrades A/B-able.
