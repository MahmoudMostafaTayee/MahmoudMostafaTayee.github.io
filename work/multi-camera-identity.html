01The problem

The testbed had thirteen cameras and no single answer to “where did that truck go?”

Each camera ran its own tracker. IDs reset at occlusion, changed when a vehicle turned, and multiplied when the same white truck passed two cameras a minute apart. Plates were often unreadable at distance or at an angle. The operations team needed a journey, not a wall of feeds.

The hard constraint was trust. Merging two different vehicles is worse than leaving them separate: a wrong global ID contaminates every event, visit, and report built on top of it. The system had to be fast, but above all it had to know when not to guess.

Design target: one persistent global identity per vehicle, resolved in real time, on the same GPU that runs detection, Re-ID, plate OCR, and the VLM.

02The approach

I treated identity as a decision that accumulates evidence, not a label attached to a detection. Each layer answers a different question, and each can say “I don't know.”

01

Build the detector around the site, not the benchmark

A single-class vehicle detector at 1280 px, fine-tuned on testbed footage with hard negatives — shadows, parked cars, reflections, partial views. The engine is INT8, calibrated for the target GPU, with a custom parser for the output layout the pipeline expects.

02

Track locally, associate globally

An IoU tracker per camera turns detections into tracklets. Appearance embeddings from vehicle crops provide the Re-ID signal. Association is gate-then-score-then-judge. The gates are cheap and physical: only vehicles first seen at designated entrance cameras, confirmed arriving, may open a global track — every other camera may only join an existing one, a single rule that eliminates a whole class of duplicated identities. Site topology declares which camera groups can plausibly follow one another and with what minimum travel time, and a max-absence TTL closes stale tracks so a returning vehicle is a new visit, never a resurrection. The score is two-zone cosine similarity against each candidate's per-camera and combined mean embeddings: below the low gate never merges, above the match threshold merges directly, and the ambiguous zone in between is never auto-merged — that zone exists for the arbiter. Global clusters grow with Union-Find under one invariant: a cluster may never hold two tracklets simultaneously on the same camera, so one vehicle can never carry two simultaneous IDs in a single view.

03

Ask a VLM only in the ambiguous band

If cosine similarity is clearly high or clearly low, the embedding decides. In the narrow band between the gate and the match threshold, a Qwen3-VL 4B model compares two candidates' per-camera, time-spread crops side by side at temperature 0 and returns same, different, or uncertain, with matched and conflicting traits. The prompt encodes multi-camera commonsense: "not visible" is not a contradiction, apparent size is not identity, and uncertain is preferred over forcing a decision. Calls run on background workers; the tracklet waits across frames for a verdict. If the wait budget expires, it becomes a new ID rather than a bad merge — unresolved is preferred over wrong.

Latency engineering mattered as much as prompt quality. Greedy decoding occasionally looped until the context cap, and shared-GPU contention could stretch one call by orders of magnitude. Hard token caps, a concise output instruction, image shrink-retries, worker pools, and a per-request wall-clock timeout got arbitration to roughly four seconds per candidate pair in the normal case. Every arbitration is logged — crops, exact prompt, verdict, latency — so "why didn't this merge?" is answerable from records, not re-runs.

04

Read the plate, keep the best crop per camera

A plate detector finds candidates on each vehicle crop. A PP-OCRv5 model, fine-tuned on Egyptian plates, reads the text through ONNX Runtime. The system keeps the best plate crop seen for each global ID in each camera, so a later clear view can replace an early blurry one. The plate is evidence, not the primary key — because the primary key cannot depend on a readable plate.

05

Make state survive restarts, and make changes provable

The next free global ID lives in Redis, not in process memory, so a sidecar restart cannot reuse an ID the app already attributes to another vehicle. Modules are isolated, model weights are versioned, and a golden replay checks that a pipeline change did not silently alter what gets published.

03Architecture

The perception sidecar runs on the GPU; the application consumes metadata from Redis. MTMC, plates, and box stabilization are independent modules, and a product is a YAML list of the modules it wants. That isolation is what let the same pipeline serve a different camera set without rewriting the engine.

The VLM is deliberately outside the per-frame path. A call takes seconds, while a frame budget is milliseconds; putting it inline would stall the tracker. Instead, the association layer submits a job, keeps the tracklet in a pending state, and resolves it when the verdict arrives or the budget expires.

Why a VLM at all? Embeddings are good at “same colour, same shape.” They are bad at “same truck, different angle, one crop shows only the cab.” The VLM is used exactly there — a small, expensive adjudication layer over a cheap, high-recall candidate generator.

04What I owned

  • MTMC architecture: tracklet management, topology-aware candidate generation, global ID lifecycle, and the pending-verdict state machine.
  • VLM arbitration: prompt and schema design, background worker integration, wait budgets, repetition-loop mitigation, and fallback behaviour.
  • Detector integration: testbed-specific fine-tuning, INT8 engine build, custom output parser, and threshold calibration.
  • Plate pipeline: detector integration, fine-tuned OCR, best-crop-per-camera bookkeeping, and evidence output.
  • Reliability: Redis-backed ID persistence, module isolation, golden-replay checks, and per-model GPU budget measurement.

On the 13-camera recorded testbed, the module produced one persistent global ID per vehicle across hand-offs. Ambiguous pairs were either confirmed by the VLM or deliberately left as new tracks; the system never forced a merge it could not justify. Global IDs survived sidecar restarts, and plate reads were attached to the identity rather than to a single camera.

The VLM path was bounded: after fixing repetition loops in the model output, the mean verdict dropped to about 4.1 seconds over the benchmark pairs. That is still too slow for a frame loop — which is exactly why it runs asynchronously, outside the tracker.

Benchmark runs on a public academic dataset under the official IDF1 protocol told the honest story: 0.61 IDF1 with ground-truth detections, 0.32 through the real detector (baselines ≈ 0.25). The gap is diagnostic, not embarrassing — detection over-production rather than association dominated the loss, which re-aimed the optimization work at detection cleanup.

Two measured negative results shaped the association design. A homography spatial model — ground-plane projection as "spatial proof" — was instrumented and found net-negative: 27 of the 28 merges it made on opposite-side camera pairs were wrong vehicles, because bottom-centre projections are orientation-biased (front vs rear of the vehicle); it was demoted to opt-in for verified tight pairs only. And the shipped Re-ID encoder turned out to be an ImageNet-pretrained ResNet50, not a formally vehicle-trained one — the benchmark harness on real site footage showed it beat the domain-trained model handily, so domain training lost to measurement.

06Reflection

The most important design choice was refusing to guess.

A duplicate ID is recoverable: an operator can merge two tracks later. A wrong merge is not: every event, visit, and report attached to that identity is now contaminated. Designing the uncertain path first made the rest of the system easier to reason about.

The next improvements are calibration and active learning: ground-plane speed to tighten travel-time gates, plate confidence fused across cameras and time, and a review queue for the uncertain band so the model learns from the cases it cannot solve.
